# BYS Volunteer Portal

موقع مبادرة BYS (تعليمية/تطوعية) — موقع تسويقي عام + بوابة داخلية للمتطوعين.

## التقنيات المستخدمة

- React 18 + Vite
- React Router (التنقل بين الصفحات)
- CSS Modules (كل كومبوننت له ملف تنسيق خاص بيه)

## تشغيل المشروع محليًا

```bash
npm install
npm run dev
```

هيفتح على `http://localhost:5173`

للتأكد إن المشروع هيبني صح قبل أي رفع (Vercel هيرفض أي build فيه أخطاء):

```bash
npm run build
```

## هيكل المشروع

```
src/
├── pages/              كل صفحة كاملة (Home, About, Join, Courses, Login...)
├── components/
│   ├── Layout/          Header + Footer + الغلاف العام (MarketingLayout)
│   ├── Marketing/       كومبوننتات الموقع التسويقي العام
│   ├── Courses/         كومبوننتات صفحة الكورسات
│   └── Forms/           الفورمات (تقديم المتطوعين/الطلاب، تسجيل الدخول)
├── context/             حالة تسجيل الدخول (VolunteerAuthContext)
├── data/                كل البيانات القابلة للتعديل (كورسات، محافظات، أخبار...)
├── services/            نقاط الاتصال بأي Backend مستقبلي (حاليًا Mock فقط)
├── routes/              كل الـ Routes في ملف واحد (AppRoutes.jsx)
└── styles/              الألوان (tokens.css) + الأساسيات العامة (global.css)
```

**قاعدة عامة:** أي بيانات ممكن تتغيّر بكرة (قايمة كورسات، محافظات، أدوار متطوعين...) موجودة في `src/data/` كملف JS منفصل. لما يتوصل Backend حقيقي، دي هي البيانات اللي المفروض تيجي من API بدل ما تكون ثابتة في الملف.

## الصفحات بالتفصيل — إيه المطلوب من الباك اند لكل واحدة

### `/` — الرئيسية
**الوظيفة:** واجهة تسويقية عامة، بتعرض آخر الأخبار وأهم الكورسات، وفورم تواصل بسيط.
**الحالة الحالية:** كل البيانات ثابتة (`data/news.js`, `data/coursesPreview.js`). فورم التواصل بيرسل "Mock" (بس يطبع في الـ Console، مفيش إرسال فعلي).
**المطلوب من الباك اند لاحقًا:**
- API يرجّع آخر الأخبار (list) بدل الملف الثابت.
- Endpoint لاستقبال رسائل فورم "تواصل معنا" (اسم، إيميل، رسالة) — يا إما يتبعت إيميل مباشرة، يا إما يتخزّن في قاعدة بيانات عشان المراجعة اليدوية.

### `/about` — من نحن
**الوظيفة:** محتوى تعريفي ثابت (رؤية، رسالة، أهداف، قيم).
**الحالة الحالية:** كل المحتوى ثابت في الكود.
**المطلوب من الباك اند:** مفيش حاليًا — الصفحة دي محتواها تحريري بحت، غالبًا هتفضل ثابتة إلا لو حبيتوا تديوا الفريق لوحة تحكم (CMS) لتعديل النصوص من غير كود.

### `/courses` — الكورسات
**الوظيفة:** استعراض كل الكورسات المتاحة، فلترة بالمجال/المستوى/الاسم، وعرض تفاصيل كل كورس (وصف + قائمة محاضرات).
**الحالة الحالية:** كتالوج الكورسات ثابت بالكامل في `data/coursesCatalog.js`. قائمة المحاضرات بتظهر "مقفولة" (🔒) لو المستخدم مش مسجّل دخول، ومفتوحة لو مسجّل.
**المطلوب من الباك اند:**
- Endpoint يرجّع قايمة الكورسات (مع كل الحقول: المجال، المستوى، المدة، المحاضر، الوصف، قائمة المحاضرات).
- Endpoint لكل محاضرة يرجّع رابط الفيديو/المحتوى الفعلي — **بشرط التحقق إن المستخدم مسجّل ومقبول** قبل ما يرجّع الرابط (ده أهم نقطة أمان في الصفحة دي، الفرونت إند حاليًا بيتأكد بس شكليًا من غير أي حماية حقيقية).
- لو هيبقى فيه "نسبة تقدّم" حقيقية للطالب في كل كورس، محتاجين جدول بيربط (مستخدم × كورس × محاضرة مكتملة ولا لأ).

### `/join` — انضم لنا (التقديم)
**الوظيفة:** فورم تقديم واحد بمسارين: "متطوع" أو "طالب لحضور كورس"، بحقول مختلفة لكل مسار (بيانات شخصية، صورة بطاقة، CV للمتطوع؛ بيانات أساسية + الكورس المطلوب للطالب).
**الحالة الحالية:** الفورم كامل ومتحقق منه بالكامل (Validation) في الفرونت إند، لكن الإرسال النهائي "Mock" — البيانات والملفات بتتبني في `FormData` وبعدين مفيش استدعاء API حقيقي، بس Log في الـ Console.
**المطلوب من الباك اند (أهم صفحة محتاجة شغل باك اند):**
- Endpoint يستقبل `multipart/form-data` (بيانات نصية + 3 ملفات: صورة بطاقة أمام، صورة بطاقة خلف، CV) لمسار المتطوع.
- Endpoint مشابه (من غير ملفات) لمسار الطالب.
- تخزين آمن للملفات (صور البطاقة والـ CV بيانات حساسة — محتاجة تفكير في الأمان والصلاحيات، مش تخزين عام).
- قاعدة بيانات لتخزين الطلبات + حالة كل طلب (قيد المراجعة / مقبول / مرفوض) عشان فريق المراجعة اليدوية يشتغل عليها.
- عند القبول: إرسال إيميل للمتقدّم (ده اللي هيفتحله `/login` و`/volunteer` أو `/courses` فعليًا).

**ملحوظة:** كان فيه صفحة `/apply` منفصلة بتعمل نفس اللي `/join` بتعمله بالظبط — اتشالت والمسار بقى تحويلة (`redirect`) لـ `/join`. **`/join` هي الصفحة الوحيدة المعتمدة للتقديم من دلوقتي.**

### `/impact` — إنجازاتنا
**الوظيفة:** عرض إحصائيات، تايم لاين لتاريخ المبادرة، معرض صور، وآراء المتطوعين/الطلاب.
**الحالة الحالية:** كل البيانات ثابتة (`data/stats.js`, `data/timeline.js`, `data/gallery.js`, `data/testimonials.js`).
**المطلوب من الباك اند:** غالبًا مفيش حاجة عاجلة — الإحصائيات ممكن تتحدّث يدويًا بين فترة وفترة. لو حبيتوا الأرقام تتحدّث تلقائيًا (عدد الطلاب الفعلي مثلاً)، محتاجين Endpoint يحسبها من قاعدة البيانات.

### `/faq` — الأسئلة الشائعة
**الوظيفة:** أسئلة مقسّمة لـ٣ فئات (طلاب/متطوعين/عام) بشكل أكورديون.
**الحالة الحالية:** كل الأسئلة والإجابات ثابتة في `data/faq.js`.
**المطلوب من الباك اند:** مفيش — محتوى تحريري بحت.

### `/login` — دخول المتطوعين
**الوظيفة:** المستخدم بيكتب اسمه ويختار دوره من قايمة، وبعدين بيتحول لـ `/volunteer`.
**الحالة الحالية:** ⚠️ **ده مش نظام دخول حقيقي خالص.** مفيش باسورد، مفيش تحقق من هوية، البيانات بتتخزن بس في `localStorage` بتاع المتصفح (`context/VolunteerAuthContext.jsx`). أي حد يقدر يكتب أي اسم ويدخل.
**المطلوب من الباك اند (أولوية عالية):**
- نظام تسجيل دخول حقيقي (إيميل + باسورد، أو OTP، أو أي طريقة تحددوها) لمتطوع اتقبل طلبه فعليًا.
- الحسابات بتتعمل يدويًا من فريق المبادرة بعد قبول الطلب (مفيش تسجيل ذاتي/Sign Up عام — ده قرار متفق عليه من الأول لأسباب أمان).
- Endpoint للتحقق من الجلسة (Session/Token) عشان `/volunteer` و`/courses` يتأكدوا إن المستخدم فعلاً مسجّل ومقبول قبل ما يوروه أي محتوى حقيقي.

### `/volunteer` — بوابة المتطوع
**الوظيفة:** لوحة تحكم شخصية للمتطوع — رسالة ترحيب، المهام الحالية، خطوات التوجيه (Onboarding)، ملفات وموارد، وبيانات التواصل مع المسؤول المباشر.
**الحالة الحالية:** كل البيانات ثابتة (`data/tasks.js`, `data/onboardingSteps.js`, `data/resources.js`) وموحّدة لكل زائر — مش مخصصة فعليًا لكل متطوع. لو مفيش تسجيل دخول (`/login`)، الصفحة بتحوّل تلقائيًا لصفحة الدخول.
**المطلوب من الباك اند:**
- كل البيانات دي المفروض تيجي **مخصصة لكل متطوع** مش ثابتة: مهامه هو، حالة كل مهمة (قيد التنفيذ/منتهي)، خطوات التوجيه اللي أكملها فعلاً (مش بس شكل بصري في الفرونت إند)، ومسؤوله المباشر المحدّد له.
- Endpoint لتحديث حالة "خطوة توجيه" لما المتطوع يعلّم عليها (حاليًا بيتغيّر بصريًا بس بره أي حفظ حقيقي).

## ⚠️ حاجات معروفة لسه محتاجة شغل

- **مفيش Backend حقيقي لحد دلوقتي** — كل الفورمات (`applicationService.js`, `contactService.js`, `joinService.js`) بتعمل Mock بس. الملفات دي بالظبط هي المكان اللي هيتغيّر لما يتوصل API حقيقي — مفيش داعي نلمس أي كومبوننت تاني وقتها.
- **`/login` و`/volunteer` مفيهمش أي حماية حقيقية** — تفصيل مهم جدًا لفريق الباك اند قبل ما يتفتح المشروع للعامة.
- **حساسية أسماء الملفات (Windows vs Linux):** لو حد بيشتغل على ويندوز وعمل ملف باسم مختلف شوية عن الاستيراد (حرف كبير/صغير)، المشروع هيشتغل عندك محليًا لكن هيفشل وقت الرفع على Vercel. لو حصل خطأ زي `Could not resolve "..."` وقت الـ build، أول حاجة اتأكدوا منها هي إن اسم الملف مطابق للاستيراد **بالحرف بالظبط**.
